# 交付与正式开发 · v2

用户认可核心玩法是90+的必要条件。达到90+后才进入以成熟原型为前提的正式交付；提前准备交付材料可以自主进行，但不得提前宣称接收完成。

## 共同交付内容

提供可定位版本、运行方式、贯通设计底稿、有效决定与原始需求回链、实现／配置的权威位置、表现规则与资源来源、实际验证场景及限制、已知问题与技术债、下一项正式开发目标。用[验证与交付索引](../templates/verification-and-delivery.md)连接已有文件，不默认再抄一套 Input／MVP／Spec／策划说明。

保留可恢复基线和必要失败证据；不要求交付全部聊天或归档全部中间文件。路径与命令由 Agent 实际核对，不能让接收者先猜文件名或安装方式。

## 两条接收路径

### 有效决定的逐项接收（两条路径共同要求）

交付者提供原始需求、已接受简报和完整决定索引的可访问位置、版本/哈希，以及FromDemoToSpec后续实际采用的变更；不能仅交本版实现清单而丢掉延期的完整产品方向。接收者在已有底稿/决定记录或项目接收表中，逐项写清来源ID、继承/暂缓/范围内变更/替代/待复核、当前归属及下一动作。登记来源的全部决定要有去向，不要求复制全部聊天，也不强制新增独立文档；无Brainstorm则按真实来源处理，没有来源不伪造。

“暂缓”是已定但当前不做，不是尚未决定；“继承”不是已实现或体验已验证。原型局部变更只在批准范围内有效，不自动覆盖完整游戏。例如单场逃脱阈值不自动等于跨场失利预算；原型不做养成也不等于取消已接受的成长方向。替代/范围变更回链真实用户决定，不能用实现事实覆盖产品授权。

后续讨论、写Spec或实施前，先查相关接收项和原文，只询问真正的细则缺口或新冲突。来源不可达、版本漂移、冲突未解时保留待复核，仅阻断依赖部分；不能静默继承或要求用户重复决定。旧关闭档案保持原样，当前决定与实现证据分别拥有。

接收完成证据包含覆盖检查与关键语义核对；文件齐全、导出成功或ID计数只能证明结构，不能替代上述实际消费。形式可复用接收项目已有maintenance规则；后续变更仅更新受影响项。

| 条件 | single-file | maintained-project |
|---|---|---|
| 原型交付必须提供 | 可运行封装、行为与表现基线、必要数据、核心场景、重建边界 | 版本化源码、依赖与构建方式、资产、架构边界、测试／诊断、增量目标 |
| 接收检查 | 接收 Agent 按说明启动并核对基线、定位规则及证据，明确重建所需输入 | 接收 Agent 从交付版本构建、实际运行，完成一项真实小改动并回归 |
| 接收结果 | 基线可消费且迁移缺口明确；不要求原型阶段复现目标引擎 | 接收记录覆盖构建、运行、改动差异和相关回归，发现的阻碍已处理 |
| 下一阶段 | 在目标正式环境重建核心体验，逐项比较基线 | 在现有工程继续功能切片，按需局部重构 |

接收者是实际承担后续工作的 Agent／任务，而非原作者自填“接收通过”。若用户明确安排同一 Agent 继续，也需从交付入口按接收步骤实际操作并记录执行者、版本和证据，不能省略步骤；无需为了形式固定创建新任务。小改动优先使用真实下一需求；没有自然需求则选有实际维护价值的有界改动，不能用文档拼写修改冒充工程接收。

多文件的90+侧重接手准备，实际构建／运行／小改动／回归在随后交付完成；不互相等待。单文件接收完成可以与“目标引擎重建尚未开始”同时成立。

## 接收记录与失败恢复

记录源版本、接收环境、操作者、执行命令与结果、产物证据、小改动目的与差异（多文件）、回归范围、阻碍与处理，以及剩余正式开发任务。机器校验只支持已读证据的完整性，不能创建真实接收事实。

构建失败回到依赖／工程 owner；行为冲突回到底稿与有效决定；信息不清回到交付入口；体验变化回到用户拥有的决定。失败不抹掉已有有效结果，不整体重建成熟工程来逃避定位问题。

## 正式开发的默认工作方式

1. 从接收基线确定本里程碑的产品目标、平台要求、范围、预算和验收场景。原型认可不自动等于整个正式产品范围已批准。
2. 为下一项功能写有界切片：目标、进入／退出、规则、输入、表现、数据／存档迁移、影响模块、验证和恢复。直接引用有效底稿，无需重写完整总设。
3. 先解决已证实会阻碍该切片的技术债，再实现规则、操作和表现；仅对有实际问题的边界局部重构。保留可比对行为与回归，避免无目的重搭架构。
4. 在正式目标环境运行切片，复验受影响范围和平台行为；更新有效设计、决定、债务及下一动作。
5. 涉及核心体验变化时重新确认认可覆盖；普通实现与修复自主完成。依里程碑逐步扩大内容和正式能力。

正式生产所需的存档迁移、平台输入、发布渠道、性能、联网／服务、可访问性及运维只在项目实际需要时纳入。范围未定时列待选项，不生成虚假的全平台完成清单。发布、外发、商店上线与购买仍需对应授权。

## 当前框架能力边界

本协议提供通用承接框架、模板与可验证合同；具体引擎工程模板从下一款真实项目经构建和切片验证后提取。框架测试、示例或接收夹具不证明真实游戏达到80／90+，也不证明跨品类成本收益。
