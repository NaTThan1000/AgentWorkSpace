# 表现与反馈 · v2

表现是有效验证的必要条件。玩家不仅要知道结果，还要感到动作、力度、节奏和情绪；整体方向要协调。文字提示不能包办所有反馈，装饰密度和素材数量也不证明质量。

## 默认由 Agent 在实际构建内校准

1. 从体验目标确定少量可执行约束：主体识别、信息优先级、颜色与形状语义、节奏与力度、资源排除项。用户主动给的参考及已定方向优先，不要求额外交美术需求。
2. 制作代表性可玩片段，在实际目标视口检查操作前、中、后及失败状态。规则、交互与反馈同时成立后再扩展。
3. 复用已有效的组件、布局、间距、状态语义和反馈规则，按具体行为调整力度；不能把相同特效机械套给所有结果。
4. 在真实构建复现关键状态与过程，检查遮挡、可读性、输入竞争、音画时序、状态恢复和异常路径。
5. 修复内部检查发现的问题后交付可玩 V1，由用户集中判断体验。反馈转成可定位问题、改动与回归。

不默认建立六阶段人工批准链、三套候选页、独立静态屏幕包或逐元素签字。普通方向 Agent 自主选择并记录理由。只有现有依据不足且选项明显改变体验的重要分歧，才带可审阅片段和推荐提前询问。

## 最小校准记录

用项目内一份短记录连接约束、关键反馈与运行证据；字段可并入设计底稿：

| 关键事件／状态 | 玩家应理解／感到什么 | 前／中／后表现 | 并发、失败和恢复 | 构建与证据 |
|---|---|---|---|---|
| 示例：资源不足而无法行动 | 成本不足，输入已收到，仍能选择其他行动 | 操作前成本提示；按下短促拒绝反馈；余额定位与可选行动保留 | 不扣费、不锁输入、不闪成成功色 | 示例待运行，无真实 PASS |

状态 ID 仅在复现与引用需要时引入，不为所有像素登记 ID。截图、录制、批注、审阅视图按诊断需要生成，优先复用游戏真实组件，避免单独搭一个与运行时漂移的审阅产品。

## 三方面底线

- 理解：目标、主体、可操作对象、危险、资源变化与结果可区分；不能只依赖颜色；重要原因有冗余线索。
- 感受：适用的预备、响应、过程、命中／结果、余韵与恢复存在，输入有回应，音画与规则时刻对应；不能只有日志表示发生过。
- 一致性：布局、尺度、轮廓、材质／色彩、文字、运动、音频强度遵循同一方向；关注点不被无关动效抢走。

检查首次进入、默认、选择／悬停（适用时）、执行、连发／连续操作、结果、受损／失败、结束／重开及必要异常。隐藏信息和实时玩法用适配的诊断方式，不把内部状态泄露到玩家视图。

诊断与玩家体验共用有效状态，诊断开关不改变规则。按实际需要分离背景、运动、特效、音频等干扰因素；不强制每个项目放四个按钮或固定左右调试面板。减弱动态和音量控制随目标设备与体验需要实现。

## 资源来源与工程消费

| 来源 | 项目处理 | 复用边界 |
|---|---|---|
| 已审计 PrototypeAssets 导出 | 显式选择 ID 和哈希，保留许可、来源与导入记录 | 不复制整库；资源仓不是运行时依赖 |
| 项目自绘、程序生成或 AI 生成 | 记录作者／工具、生成与加工来源、可确认的使用条件；实际检查风格和技术质量 | 不自动晋升为已审计公共资产 |
| 外部或用户提供资源 | 核对实际来源、可用范围与许可；条件不足则不作为已审核交付资源 | 不因收到文件而推断公开再分发许可 |

未知／隔离资源保持不可用状态或以合规替代物替换；不把检索图片直接当素材。项目内生成可直接在明确授权和可用条件下验证，无需先建设共享资产库。可信资源晋升由资源仓维护流程拥有，本流程不自动入库。

单文件在最终封装时内联实际使用的资源；可持续工程保留项目资源文件、导入设置及版本。两者均记录来源和哈希，拒绝越界路径、篡改、未经许可的公开分发，保留离线检查能力。表现选择的自主权不等于资源许可。

## 何时展开

跨多屏共享组件、复杂时序或交接出现信息损失时，按实际问题增加屏幕／状态表、时序图、资源替换表及回归集。已有真实项目中的校准证据继续保留；简化新项目默认流程不改写旧验收结论。
