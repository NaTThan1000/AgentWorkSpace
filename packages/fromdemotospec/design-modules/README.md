# 按需设计模块

默认只维护贯通底稿。遇到需要更精确推理的领域问题时，读取对应模块，把实际结论写回底稿／实现／验证；无需填完全部题目或产生每类 Spec。

| 实际问题 | 模块 |
|---|---|
| 多系统依赖、规则冲突、职责不清 | [系统与接口](systems-and-boundaries.md) |
| 战斗、实时输入、空间与动作后果 | [行动与战斗](actions-and-combat.md) |
| 资源循环、构筑和成长差异 | [经济与成长](economy-and-progression.md) |
| 信息、谜题、叙事选择与玩家理解 | [信息与体验](information-and-experience.md) |

四层模型的价值是分清体验承诺、上层结构、职责依赖和可执行规则，并检查它们能否相互支持。简单项目直接用行为表更便宜；复杂项目可添加层级、接口图或状态机；没有证据证明某一种层数普遍最优。

Research Weapon Farm 样本可在制作定义后查设计遗漏、复杂系统展开或交付复核时作结构参考。仅借用问题意识，记录来源与适用性；来源／许可未核实，不复制正文、内容设计或实验结论进项目及发布包。GameAnalysisDecision 负责需要证据的分析，Knowledge 提供资料；它们都不是每个模块的必经审批链。
