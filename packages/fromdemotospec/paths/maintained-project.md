# maintained-project · 可持续工程路径

适合沿用原型代码与表现继续开发的项目。实现前确定正式环境，不将任意多文件 Demo 宣称为正式工程基础。

## 选型合同

明确目标平台与设备、引擎及必要版本、语言、依赖管理、构建／启动／验证命令、主要输入，以及实际相关的存档、联网、平台接口、资源管线和性能约束。Agent 同时评估玩法适配、后续目标与自身实际编辑／运行／诊断能力。重要长期取舍提供具体推荐；已有决定足够则自主选定。

未决项标明阻断哪些动作；普通内容设计可以继续，不能在正式环境未知时先实现大量需重做的工程。没有实际需要的服务和工具不提前建设。

## 工程起点必须实际运行

在用户指定或专属项目目录初始化目标工程；保存版本与可重复依赖信息、环境要求和平台必要设置。真正执行构建、启动和输入，完成规则到表现的最小链路后才称起点可用。失败记录实际报错和恢复入口，不能以目录存在代替运行。

[项目入口](../templates/project-entry.md)记录从干净接手环境恢复的方法。引擎特有的编辑器导入、构建配置、资源单位、压缩和输入设置必须纳入项目，不能藏在作者本机。

## 工程职责与维护

按实际复杂度分离规则／状态、内容数据、输入、表现／UI、资源与生命周期；接口围绕可解释的行为，不为未来可能性堆抽象。规则可独立验证，表现从有效状态或明确事件得知变化；UI 不掌管核心规则。数据有单位、约束与引用；并发输入、异步动画和场景退出有明确恢复行为。

资源保留项目文件及实际导入设置，用清单连接来源、许可、加工与哈希。依赖可重建，生成产物与手工源分开。存档、回放、联网、编辑工具按项目需求加入，明确版本与迁移；不默认要求全部能力。

诊断满足真实问题定位：错误、状态、关键事件、复现场景；隐藏信息不泄露到玩家体验。性能目标来自实际设备与场景，检查真实瓶颈后优化，不能仅凭平均帧率判定体验稳定。

## 从原型继续生产

每个功能切片同时处理规则、输入、表现、验证、文档及必要债务。改动前识别影响模块、认可和证据；保留未受影响部分。不得因原型身份就整体推倒已有效的逻辑和表现。

交付必须由接收 Agent 实际构建、运行、完成小改动及回归，见[接收协议](../protocols/handoff-and-production.md)。下一款真实项目选定技术栈后才能形成经验证的工程模板；本合同自身不是任何引擎的可运行模板。
