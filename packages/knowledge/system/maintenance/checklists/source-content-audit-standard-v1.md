# 全文映射审核规范 v1

> 状态：`SOURCE_CONTENT_AUDIT_STANDARD_FROZEN_V1`
>
> 适用：新写 Stage 1 与历史 raw 内容回测。
>
> 原则：消化稿以映射全文为基准，再判断哪些内容可合并、可省略或必须还原；不得先按“重点”过滤原文。

## 一、固定执行顺序

1. 只从全部 clipping 生成 source manifest；标题、段落、列表、表格行和媒体均须进入全集，多来源分别保留来源 ID。
2. 逐单元比较 clipping 与 raw，先判断 `coverage_status`，不得读取或采信写作者的“正文充分”等自评。
3. 在覆盖事实确定后，再判断 `retention_policy`；“非核心”“太细”“与主题弱”不能单独作为省略理由。
4. 应用全部逐单元裁决并运行机器验证；单元缺失、重复、非法行号、哈希漂移和结论不一致均算结构异常。
5. 将内容阻断与结构异常分开报告。历史 raw 有真实缺口时，收据失败是正确结果，不得为了关闭样板而改成通过。

## 二、两轴通过矩阵

| 保留策略 | 允许覆盖事实 | 结果 |
|---|---|---|
| `required` | `complete` | 通过 |
| `required` | `partial / missing / distorted / uncertain` | 阻断 |
| `optional_supporting` | `complete / partial / missing` | 通过，但保留真实覆盖事实 |
| `optional_supporting` | `distorted / uncertain` | 阻断 |
| `retain_media_marker` | `marker_only`，且映射行含固定留标 | 通过 |
| `retain_media_marker` | `missing / uncertain` | 阻断 |
| `omit_*` 严格白名单 | `not_applicable` | 通过 |

严格白名单只有：严格重复、非语义媒体、来源/站点元数据、不承载主文内容的二级评论。不存在通用的 `omit_irrelevant`。

## 三、跨文体必保尺度

所有文体都必须保留：

- 定义、命题与结论；
- 机制、流程、步骤及输入/输出；
- 因果链和决策理由；
- 边界、例外、取舍与失败条件；
- 数据、枚举、比较维度；
- 支撑结论的唯一例证；
- 对作者思路有决定作用的发展背景或后果。

可以合并表达，但合并后仍须能从 raw 还原上述独立含义。相邻段落谈到同一主题，不等于已经覆盖该单元。

## 四、文体校准

### 访谈、回顾与思想史

- 区分氛围性经历与决定设计思想的关键背景/后果。
- 编辑、译者或二级评论不因身份自动省略；先判断是否总结或推进主文。
- 保留人物观点如何形成、改变及产生后果，不能只留最终主张。

### 方法论

- 必保定义、步骤顺序、输入/输出、操作条件、因果解释、边界和反例。
- 示例可合并，但承担步骤说明、参数关系或唯一操作证据时必须保留。
- 设问、转场、重复图注可判为 `optional_supporting`，不得顺带省略其后的答案或图中独立信息。

### 案例分析

- 必保案例事实、比较维度和“事实→判断→设计启示”的完整链。
- 装备、属性、系统和玩家行为等细节可合并；若是判断的唯一证据则必须保留。
- 多篇 clipping 合成一篇 raw 时逐来源审核，不能以一篇的完整度抵消另一篇遗漏。

## 五、图片能力降级

1. 装饰图、普通视觉示例或被正文完整重复且不承载独立信息的图片，可记为 `not_applicable + omit_nonsemantic_media`。
2. 能可靠读图时，转录与正文论证有关的关键信息，再按普通语义单元判断覆盖。
3. 图片可能承载布局、参数、顺序、数值或对照信息，但当前无法可靠读图时，raw 必须显式写“原文含信息图片，未转录”。
4. 已留标记为 `marker_only + retain_media_marker`；未转录且未留标记为 `missing + retain_media_marker` 并阻断。
5. 不能只凭“相邻正文谈到了同一主题”推定图片没有独立语义。

## 六、人审与展示边界

每篇完整保留 manifest、decisions 和 receipt；现行 source-audit-vnext 在内部重建逐单元 review，常规通过不重复持久化 review。历史 source-content-audit 的 review 入口继续用于按原格式复验；新批次不同时跑两套等价审核。全量人读包只在以下情况展示给用户：

- 规则或白名单变化；
- 新来源结构或新解析单元；
- 用户判断与审核冲突、异常率突变；
- 定期抽检或用户明确要求。

规范稳定后的常规批次，只展示摘要、失败项和抽检证据。校准阶段若用户明确说明某整区抽查后通过，可将该区未逐项填写的条目归一化为通过，但闭合记录必须保留抽查范围和用户结论；不得把这种归一化扩展为机器审核免检。

## 八、完成判据

- 100% 来源单元有唯一裁决；
- `reviewer_contract.independent_pass = true`，且不使用写作者自评；
- 结构异常为 0；
- 所有内容阻断如实列出；
- 新写 Stage 1 必须无内容阻断才可通过；
- 历史回测允许收据失败，但只能表示“审核正确发现旧稿缺口”，不能宣称 raw 已修复。

## 九、生成前规划与验证解释

生成前 manifest 固定来源全集与版本；写作骨架覆盖全部单元，包括后文限定、图表与叙事背景。骨架的保留意图不等于生成后的覆盖事实；两轴裁决只能在实际回读 source→raw 后形成。

先检查定义/边界、长论证、数字单位、因果背景、独立媒体、跨来源冲突与唯一例证。每种失真有具体修复位置；不可用低风险单元的大量 complete 抵消 required 缺口。数字/标题/行号匹配是定位证据，独立回读才是语义判断；receipt 的 passed 表示所提交裁决满足结构和门禁，不能自行证明裁决真实。

[实作及反例](../../examples/ingest-content/README.md)给出生成前规划、合格/不合格文本与修复过程。规则减检只在反例和同类来源验证覆盖后限定采用；未证明收益继续保留现行完整裁决。来源、raw 或规则变更使依赖证据失效，未变且范围一致的机械结果可复用，不重造第二份权威语义。
