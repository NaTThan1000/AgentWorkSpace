# 随任务发生的方法维护

维护运行方法及案例，不拥有项目决定或长期个人画像。以[来源政策](../docs/research/source-policy.md)区分来源、可执行资格和收益；项目/FromDemoToSpec学习反馈仍由其原合同处理。

在当前任务的反馈、失败、来源或交付结果可能有可复用增量时，执行：

1. 定位实际触发材料与受影响方法/路由；先查是否已处理。相同材料+相同问题+相同改动重复输入不再次修改。
2. 明确旧行为、拟改操作、适用任务、代价、反例和恢复依据。通常复用方法案例、版本diff或任务审计，不建另一长期知识库。
3. 确定性算术/引用错误直接修正并验证；新策略先限具体缺口有界尝试，不用“发现论文”直接全局默认。
4. 运行受影响合同，语义审读检查步骤是否实际处理了反例。需证明效果时使用合适对照，不把结构PASS或本方法的合成示例当未见收益。
5. 有增量再改正文/案例/路由并记范围；无增量不强制加方法。新反例收窄、撤回或替换，保留旧证据和失败。新方法仍从placeholder起，不能冒充正式ready。

最小留痕可直接附在任务审计或方法维护记录：触发指针、修改对象/版本、依据与适配、验证结果、使用范围、反例/恢复点。同一份记录即可，不需要并行审批台账。

Agent可完成来源和语义审读，只有触及正式产品取舍或新权限才交用户决定。学习不产生自动spawn、调度、个人记忆或外部发布授权，不修改Knowledge的Clippings/raw/raw-sources/wiki，不改变已接受DEC。

确定性纠错实例见[内容审读](../docs/research/public-sources.md)：6-3-5公式、来源误分类与错链已定位；这是纠错依据，不是新版创意收益。运行中的局部适配不必等维护记录结束。

## 工具入口

具体学习记录的字段、去重、采用/收窄/撤回与权限验证，以[方法学习合同](../docs/method-learning.md)及实际CLI为准。本文仅说明专业维护如何使用该合同，不另建状态机。

`node scripts/method-learning.mjs validate --input <json>` 检查记录，`record --input <json>` 留痕；正文改动仍须Agent实际完成和验证，工具不会自动证明效果。
