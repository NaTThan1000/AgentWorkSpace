# First Principles

## Contract

- Method ID: `first-principles`
- Category: `framing`
- Status: `ready`
- Content version: `2`

公共约束见[方法操作约定](../OPERATING_GUIDE.md)。

## Purpose

拆事实、目标、推断与惯例，再从必要关系重建，不以“第一性”代替来源。

## Input contract

受惯例约束主张，可读事实与资源边界。

## Use when

同类都这样阻止探索，想检查机制是否必需。

## Avoid when

兴趣未清或事实待查；不能分解掉用户偏好。

## Procedure

1. 依赖分为事实、目标/约束、推断、惯例，事实写来源。
2. 只继续分解会改变下一选择的项，不追求不可再分真理。
3. 固定目标事实，移去无依据惯例，构造别的路径。
4. 写事实+新增假设→机制→后果，不称设计推演为必然。
5. 事实缺口按需Knowledge/Web，实质因果争议按需GameAnalysisDecision，未取结果标unknown。

## Output contract

依据分类、重建关系、候选与新增假设，可确认原路径合理。

## Exit conditions

找到隐藏选择或决定性未知即停，不为新颖推倒重来。

## Single-user + AI adaptation

Agent查证重建，用户供不可读取的目标取舍；哲学来源不证明算法普适。

## Traceability

候选关联事实和新假设，保留原方向与原话。

## Evidence boundary

历史哲学/实践来源仅作谱系，有限分解和目标保护为本仓适配。

## Behavior cases

### Positive case

`CASE-FP-P01`：合成事实：一人维护的工具每日一次交接。旧主张必须实时群聊。必要关系是交班人留下异常、接班人确认，得到交班卡+已读确认。接班打开能看未结项；突发升级仍未知，不因此取消通知。

### Negative case

`CASE-FP-N01`：无来源说注意力仅8秒就删全部长说明。撤回事实地位，查实际行为或标假设，口号不能推出设计必然。
