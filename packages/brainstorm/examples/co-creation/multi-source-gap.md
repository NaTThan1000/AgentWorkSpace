# 多源缺证：不以链接数量或请求准备冒充证据

性质：合成协议示例，A/B/C与工具回执不是本次真实调用。

U1：“这个协作玩法是不是已经证明能提高沟通？”当前Idea I1描述成员各持一部分地图、交换信息后共同选路。需要区分“机制可解释”和“玩家效果已验证”。

材料A是某研究作者摘要，B是转述A的行业报道，C是Knowledge对A的摘要。Agent画出B→A、C→A，因此只算一条原始证据链。假设A受测的是课堂协作而非游戏，也不能直接说I1已有效。

查询目的：
1. Knowledge提供原出处和本地相关反例。
2. Web查一手研究的任务、样本和结果，核对是否有冲突证据。
3. 若证据范围复杂到影响方向，GAD做限定分析。

如果Knowledge返回unavailable、GAD仅prepare成功，则记录“请求已准备，未执行分析”，继续已有证据边界内的脑暴。不能假写来源、报告或哈希，也不自动扩大搜集直到找到支持。

当前可交付的候选：
I2让玩家先独立选路径，再可交换一条信息；关键选择是何时透露，而非只增加聊天。
I3改为同屏共同地图，用分工行动合作，降低沟通要求。
差异是信息互补与行动配合，是否提高实际沟通仍未知。

交接包含I1来源、A/B/C同源关系、不可用接口状态、I2/I3变形链和下一关键证据。没有用户选择，没有真实实验，不把“多源路线可用”写成“已多源验证”。
