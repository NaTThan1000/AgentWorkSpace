# Game Concept · Convergence Profile

## Complete option checks

完整方向能回答：玩家在什么情境行动、系统如何回应、为何继续；哪些构件共同支撑体验，哪些会破坏它；本次纳入/排除什么及理由。内容回到来源，新增推演明确为候选而非用户承诺。

- 同一组 Idea 可产生不同机制关系；实质差异不能只看 Idea 集合。
- 候选只换名称、题材或同义解释时重新变形，不凑数。脚本仅发现完全重复，差异仍需语义检查。
- 一个方向也可继续：说明为什么当前已有足够方向、已考虑的替代或保留边界，不能虚构替代包。
- 无合适方向保持 `open`；等待事实/用户想法或暂停为 `paused`。保留继续问题即可，不强求 brief。
- 所有现存未选包列为 deferred，表示本次未采用，不是正式 rejected。

## Status and decisions

| 状态 | 含义与下一动作 |
|---|---|
| combination `open` / `paused` | 无正式选择；保留候选和继续边界 |
| combination `selected` | user/joint Decision 选择完整方向；不能由高分或 component 自动晋升 |
| brief `draft` | 已选方向展开为简报，仍需核对 |
| brief `return-to-brainstorm` | 展开暴露冲突或缺口；保留历史已选事实 |
| brief `accepted` | user/joint 接受该简报范围；不是自动通过效果验证 |

正式决定、锁定边界不能被草案推翻。选包和接受 brief 的决定可以相同，但原决定必须确实覆盖动作及范围。“喜欢这个动作”不能记成接受整包。

## Scope and feedback

支柱有符合与排除信号。范围至少 prototype 与 excluded，first-playable/later 按需；这是边界，不是启动原型或排期。表现反馈帮助理解结果、风险和策略，不能以以后美化为由遗漏；无需在此定完所有工程和资源规格。

先检查机制关系再评分。例如紧张追逐配上无限随时维修，会消除绕路代价；应选择受限维修或放弃追逐承诺，不能把两项单独高分相加。

## Stop and return

抽象口号、片段需要虚构、违反硬约束、循环相互抵消、证据不足时，停止宣称收敛。按问题具体化、变形、查证、GAD 分析或等待；不为填表扩写。

`accepted` 不等于 F2S ready。F2S intent 仅 `not-requested` / `requested`，按已有授权决定；gap/渲染/接收检查不能报告为启动 F2S。
