# Game Concept Playbook

- Playbook ID: `game-concept`
- Domain: `game-design`
- Status: `ready`
- Output: `game-concept-combinations.md`（探索/选择）及按需 `game-concept-brief.md`（所选概念）

帮助用户把想玩的体验变成可想象、可比较、可继续制作的完整方向。可从模糊愿望开始，也可直接展开已有机制；不要求重走固定阶段。

## Flow

1. 从当前 Raw、Idea、决定和未决问题恢复。先展示一次具体体验：什么情境下，玩家看见什么，做什么选择，结果如何改变下一步。
2. 从回应区分没看懂、没兴趣、局部不对或理解错误。说明哪些保留、哪些改变；喜欢局部不等于接受整包。按 [METHOD_PRESET.md](METHOD_PRESET.md) 选择认知操作，不因换方法暂停。
3. 把相互支持的构件组织为完整候选，按问题选择数量，允许只有一个有依据的方向。压力、恢复和槽位只是特定游戏可能需要的变量。
4. 按 [CONVERGENCE_PROFILE.md](CONVERGENCE_PROFILE.md) 检查体验、关系、取舍与来源。多包需说明所有未选方向去向；没有合适方向保持 `open` 或 `paused`，记录下一问题，不填假概念。
5. 只有已有 user/joint Decision 才标 `selected`。选包不自动等于接受概念简报或原型意图。
6. 需要交接所选概念时按 [OUTPUT_SCHEMA.md](OUTPUT_SCHEMA.md) 创建 `draft` brief；真正接受必须回到 user/joint 决定。FromDemoToSpec 为按授权的可选下游。

## Evidence and authority

Knowledge、Web 用于事实或参考缺口，GAD 用于超出创意比较的实质分析与决定。在需要时介入，保留参考前的输入及来源，避免材料吞掉用户想法。查询准备、实际结果与未知分开。

组合不自动改写 Idea 的 Disposition / Adoption。暂存不是正式淘汰，Playbook 不获得额外授权。纯对话不能伪造持久 ID。持久运行先验证 session，再调用组合生成/校验、简报生成/校验；脚本不裁定好玩或吸引力。
