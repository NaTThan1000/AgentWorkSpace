# BRAINSTORM_PROTOCOL · 共创运行协议

当前运行：session state schema 2，record schema 2；新建与已迁移的未关闭会话统一使用新版。历史 closed 档案可只读追溯，不作为旧运行入口。

## 1. 开始与继续

服务目标是有效发散、收敛并激发用户，形成可追溯、可交付的结果。读取已有目标、非目标、约束、用户表达、当前决定及输出去向；不重复询问可读材料。只有会改变下一必要动作的缺口才追问。

默认 cocreate：先给少量具体、有实质差异的点子，根据用户反应继续探索。autonomous 只表示先自主探索再集中比较，不改变采用、淘汰和业务启动权限。quick / standard / deep 控制投入深度，不强制方法、候选数量或全视角卡覆盖。

继续持久会话先用 [resume-session](scripts/resume-session.ps1) 读取当前焦点、决定、未决问题与暂停边界。读取恢复不自动将 paused 改 open，也不把 converged 重置为发散。只在用户请求继续且业务边界允许时执行下一动作；条件认可不是实验开始授权。

## 2. 每轮有价值的共创

捕获、框定、发散、聚类、收敛、记录和交接是可回转的操作；由当前卡点选择，不必排队全部走一遍。Agent 自主选方法、整理和查证，不要求用户确认换方法。

用户看到的候选应说明：具体情境，行动与选择，结果或反馈，可能带来的感受，与其他方向的实质差异及关键未知。先用一回合、一次遭遇或一次用户旅程解释；表格、草图或轻量演练按需使用，不固定生成图片或实现游戏。

| 用户反应 | Agent 下一动作 |
|---|---|
| 没看懂 | 减少术语，补动作、结果或示意，不立即否定点子 |
| 理解但没兴趣 | 改体验承诺或发散轴，不给同一方案换名字 |
| 某一部分有感觉 | 保持该部分，围绕未满意处变形，不写整包已接受 |
| 理解需求有误 | 修正当前工作假设，保存用户原话与解释变化 |
| 无法判断 | 提供真正有区分度的对比或最小演练，保留未知 |
| 想暂停／都不适合 | 保存有用候选和卡点；开放或暂停是合法产出，不造赢家 |

内部可保留更多原始点子，面对用户聚焦展示。聚焦、归组与暂存不等于正式淘汰。避免把当前偏好扩大成永久画像；有价值时保留一个挑战既有方向的探索项。

当变体不再增加机制差异、用户重复表示没感觉或达到本轮投入边界，先改变生成方式或问题，不无限追加数量。

## 3. 方法与视角

使用 [METHOD_ROUTER](methods/METHOD_ROUTER.md) 和 catalog 选择适合当前卡点的可执行方法。方法名和来源不能保证效果；原理、Agent 适配、运行资格与效果证据分别说明。

认知变换必须落实到可理解的候选，不靠更多角色、独立上下文、更多标题或矩阵组合数证明创造性。Perspective 按需要补遗漏，不因 deep 而全部运行。只为有具体收益目的且已有授权的独立工作使用子 Agent，不把角色模拟伪装真实独立专家。

method-generated Idea 保留 Method ID、对应 Method Run 输入输出与来源。placeholder 方法不能冒充正式能力；新研究与有界试用按 [方法学习](docs/method-learning.md) 维护，rejected 历史不自动恢复。

## 4. 多源补强

Agent 在既有授权内按具体缺口请求 Knowledge、联网研究或 GAD，不等待固定口令，也不强制每轮全部调用。

- 开场事实会改变方向时可以先查；灵感刺激尽量保留介入前已有想法，说明借用了什么关系。
- Knowledge 提供材料和领域原则；Web 补时效事实、外部案例与反例。资料不足或冲突时保留条件与未知。
- 用户、ai-independent、method-generated、project-fact、knowledge、web 来源分层；模型预训练只提供线索，不冒充已查证来源。
- 转载或 GAD／Knowledge 引用同一材料不算独立互证。外部资料不能覆盖用户原始创意来源。
- 通过 [Knowledge adapter](adapters/knowledge-context-brief/README.md) 装配已有上下文，并实际执行其 Query；只有准备包时报告 prepared，不能写 finding。
- 复杂因果、关键风险、证据冲突或影响投入的取舍，使用 [GAD adapter](adapters/game-analysis-decision/README.md)。GAD 原报告是分析 SSOT，核验后直接消费；不另写同义制作人简报。
- 普通分析由 Agent 消费，重要产品选择交用户；来源不足可能只阻断相关判断，独立发散可继续。
- 工具不可用明确 unavailable；不可伪造检索、分析、专家或验证结果。查询重复且不改变方向时停止，说明剩余未知。

Knowledge 的 Clippings、raw／raw-sources、wiki 保持只读。任何调用都不自动启动 FromDemoToSpec、外发、付费或扩大权限。

## 5. 聚类与完整方案收敛

保留原始项与离群项。区分兴趣、可行性与证据未知，不用总分掩盖“稳妥但无吸引力”。使用有明确锚点的决策矩阵时保留关键未知、敏感性与排序依据。

比较的是能够共存的完整方案：核心关系、为何选择、主要代价、不采用什么、什么未知会改变选择。单个高分构件不自动加入首版。多个构件互相抵消时减法或重组，不全量拼装。

没有固定包数、槽位数或所有游戏通用的压力／恢复哲学。只有一个值得继续的方向可以比较其真实替代行动；没有合适方向则保持 open／paused。

正式采用及 confirm 下的 rejected 由 user／joint 决定。明确授权的 delegated 仅针对当前 session 与目标，保留理由、来源和历史；不能覆盖 locked decisions，也不替用户认可核心玩法。

## 6. 状态、记录与恢复

状态为 open、paused、converged、handoff-ready、closed。允许 open→paused、paused→open、open→converged、converged→open、converged→handoff-ready，以及任一未关闭状态→closed。合法迁移不等于语义通过；closed 不继续写入业务。

文件保存遵循用户路径＞宿主路径＞Brainstorm 默认 sessions。用户要求不落盘时仅在对话保留可交接结果，不伪造文件与 ID。

所有脑暴默认随讨论增量及时落盘，适用于所有主题、深度与交互模式的新建和继续会话，不仅是本次协作，也不以用户同意为记录前提。每轮结束前保存本轮用户原始表达、已向用户提出的点子与例子、比较理由、反方意见、修正、未决问题及来源；长轮次在话题切换或出现关键灵感时先做增量记录，不等收敛、提交或会话结束。

记录与拍板分开：未认可、暂存、不喜欢或被否定的方向仍保留及可追溯；用户明确同意后，当轮记录准确的同意范围与依据，再继续下一点，不等待再次要求“落盘”。局部同意不扩大为整包采用，流程约定不冒充产品决定。记录修订关系，不以新摘要覆盖旧表达。

每轮交付前核对讨论增量与记录对应、引用可恢复，并更新真实的继续位置；无需每轮新建文件或重复整份报告，也不要求记录内部推理与无关工具日志。写入失败须明确尚未保存的范围，保留可补写内容并在恢复后补齐，不声称已落盘。及时落盘不自动授权 Git 提交、关闭、发布或启动下游；用户明确不落盘的例外仍优先。

session-state.json 拥有控制状态；session.md 保存 Raw、Idea、Run、Evidence、Decision 和当前恢复信息。长分析进入 artifacts 并回链。Idea 正文修订新建 ID，保留 supersedes／destination；不能用清理日志删除原话。

Current Continuation 只写真实焦点、下一动作、暂停边界和决定引用；历史 NAV 不改成新流程记录。阶段或方法改变时可追加实际 NAV，用一句话解释有用的方向变化，不强制展示四行导航和暂停确认。状态与修订通过 [session 合同](docs/contracts/session-contract.md) 中的工具执行。

容量超限只 warning，不删除。恢复失败说明字段、来源或状态问题；不可通过降低校验绕过。旧未迁移 active 会话先一次性迁移，不提供旧继续入口；closed 档案只读保留。

## 7. 交付与学习

| 当前结果 | 交付内容 |
|---|---|
| 开放探索／暂存 | 有价值候选、当前兴趣与反例、卡点、明确恢复位置 |
| 已选概念 | 体验承诺、具体片段、核心机制／循环、采用与排除、理由、未知及用户决定 |
| 请求进入执行 | 在已选概念上映射消费者现行合同，标明缺口、下一责任和实际启动状态 |

游戏使用 [Game Concept](playbooks/game-concept/README.md)，非游戏机会使用 [Opportunity Thesis](playbooks/opportunity-thesis/README.md)。生成工件不自动被接受；概念选择也不等于真实玩法认可。

[FromDemoToSpec adapter](adapters/fromdemotospec-handoff/README.md) 映射制作定义 v2，核心体验／循环／范围有来源、阻断缺口关闭才 ready。非阻断缺口带理由与下一动作；可持续工程的正式环境由 FromDemoToSpec 在实现前明确。handoff 只准备材料，external_flow_started=false 直到真实启动；不重启既有项目。

随任务发现可复用纠错、方法改进、多源线索时，按 [方法学习](docs/method-learning.md) 验证并限定维护；无增量不强制记录或新增方法，不运行定时维护。项目学习反馈仍连接宿主 DEC 与实际 FromDemoToSpec 证据；import 不等于人工已审、Knowledge 接收或原玩法已验证。

重要采用／反馈状态判断引用用户已作决定，不能重新要求审过的事项；需要新增决定时直接呈现依据、建议、替代和最大未知。方法学习不改变权限、用户目标、正式决定或质量标准。

## 8. 完成的含义

分别报告 session 状态、brief 接受、handoff、实际执行、工程检查、效果证据、真人反馈、本地 Git 集成与发布。结构通过不等于创意有价值，模拟用户不等于激发了真人。未得到真人反馈就保留未验证；不把更多文档或满分并列当作普遍增益。
