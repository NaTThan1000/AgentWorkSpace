# 1.3.0 from 1.2.0

兼容上一版的完整 meta、三项原有业务包、compatible 审计、用户数据及既有安装位置。新增 skills、game-analysis-decision、game-presentation、prototype-assets；原有包不会因为升级自动增加新包。所有新包的可选集成见 docs/package-dependencies.md。

1. 在发布仓预览 workspace.py upgrade --target <workspace>，处理实际双方修改冲突后再 --apply。只升级已安装组件。
2. 使用 add --packages <selected-id...> 预览并添加所需新包；compatible 模式继续保留根宿主权威，只安装显式选择。
3. skills package 是库：在 modules/skills 中运行 scripts/skills.py list，再选择 --names 安装。Codex 与 CodeBuddy 的状态独立。Skill 自身不要求其他业务包；缺少可选工具时保留相应限制。
4. 新包都可以独立复制使用。GameAnalysisDecision 的学习状态为空白，不能继承私人来源的 adopted 或效果资格；需要本地学习时建立独立本地 Git 基线。PrototypeAssets 每项许可与证据随包保留。

恢复：每次实际应用返回 transaction。用同一安装工具、目标与平台 preview rollback，再 --apply。工作区事务与 Skill 事务分别管理，先撤本次 Skill 操作，再按需撤包操作；应用后的用户修改会阻止回退覆盖。保留备份和冲突证据，不改写任何旧 tag。新包未加入的原有工作区可按原来的方式继续使用。

Compatibility: the original three package IDs and paths, full meta, compatible profiles and existing user data are retained. Upgrade only installed components, then explicitly add chosen new packages. The skill library does not activate all skills or silently update selected user copies. Root and per-platform skill transactions have separate rollback histories. No source runtime dependency is introduced into games.
