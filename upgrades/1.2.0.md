# 升级到 1.2.0 / Upgrade to 1.2.0

前一版 / Previous version: **1.1.0**.

本版增加已有工作区兼容接入：能力审计、需求推荐、经审阅的替代依赖、独立 meta 安装位置和接入入口。详见[兼容模式](../docs/compatible-workspace.md)。Meta 仍只有完整版；没有新增功能组合。

This release adds existing-workspace capability audits, need-based recommendations, reviewed substitute dependencies and scoped meta placement. See [compatible mode](../docs/compatible-workspace.md). Meta still has one complete edition.

已有 v1.1.0 full 工作区在新版运行 `python scripts/workspace.py upgrade --target <workspace-path>`，核对后加 `--apply`。缺少 mode 字段按 full 解释，根 meta、用户模块、旧参数和会话格式保持现有兼容规则。不要为了使用审计强行转为兼容模式；audit 可以只读审阅现有工作区。

For a v1.1.0 full installation, preview the normal upgrade and add `--apply` after resolving conflicts. Missing mode means full. Existing root meta, modules, aliases and session formats retain their layout and compatibility. Audit can inspect an existing workspace without changing its installation mode.

新接入的已有工作区使用 `init --mode compatible`，先审计与选择，不默认安装 meta。所选包缺少 host-governance 时，选择完整 meta，或提供真实审阅、完整 criteria 与当前证据哈希的替代 provider；未满足前不写入。替代模块与根规则不归安装器所有。

New integrations use `init --mode compatible`, after audit and selection. Meta is not installed by default. Missing host governance must be supplied by selected meta or an equivalent reviewed provider before any installation writes. Existing substitutes and root rules are not managed by the installer.

兼容模式首次安装会创建 `agent-workspace-compatibility.md` 和统一 state，选择 meta 时放在 `modules/meta`。后续升级沿用 mode/profile，证据变化需重新审阅。元数据保持 schema1 的向后兼容扩展；旧版工具不能用于维护新兼容实例。

Compatible installations create an integration entry and the usual state. Selected meta is placed under `modules/meta`. Later upgrades retain mode/profile and recheck evidence. The state extension remains schema1-compatible; use a compatible-mode-aware tool to maintain these new installations.

每次 Apply 保存事务。`rollback --target <workspace-path> --transaction <transaction-id>` 先预览，再加 `--apply`；后续用户修改导致冲突时保全并人工解决。v1.1.0 full 升级可恢复原文件和 state；首次兼容安装可恢复到未接入状态，不删除原宿主内容。旧 tag 保持不变。工程验证不代表语义替代判断、长期效果或用户内容已获认可。

Each application records a transaction. Preview rollback, then apply it if there are no later conflicts. Full upgrades restore prior files/state; initial compatible installation rollback restores the unregistered state while preserving host content. Historical tags stay immutable. Engineering tests do not certify semantic equivalence, long-term effects or user content approval.
