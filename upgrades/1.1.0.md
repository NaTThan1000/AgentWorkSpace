# 升级到 1.1.0 / Upgrade to 1.1.0

前一版 / Previous version: **1.0.0**.

## 变化 / Changes

- 展示名称统一为 FromDemoToSpec；包 ID、发布目录和安装目录统一使用小写 `fromdemotospec`。The display name is FromDemoToSpec; the package ID and directory name are `fromdemotospec`.
- README 提供中文、英文互相切换的完整说明；包内详细文档仍以中文为主。The two READMEs provide equivalent instructions with language links; detailed package documentation is mainly Chinese.
- meta 加入 Humanizer-zh，保留固定来源、MIT 许可与事实保真要求。Meta includes Humanizer-zh with pinned provenance and its MIT notice.

## 升级 / Upgrade

在新版发布仓运行 `python scripts/workspace.py upgrade --target <workspace-path>`。核对文件变更和 `moves`；没有冲突后加 `--apply`。Run the command from the new distribution, review file changes and `moves`, then add `--apply` if there are no conflicts.

已安装的 `modules/f2s` 会整体重命名为 `modules/fromdemotospec`，保留用户文件，再按基线更新框架和安装记录。两个目录同时存在、旧目录缺失或包含链接时停止，保全现有目录后解决；不要强行合并或删除用户目录。The installed directory is renamed as a whole, preserving user files, before managed framework files and state are updated. Existing destination conflicts, missing sources and linked paths stop the operation.

目录内引用 `modules/f2s` 的用户自定义脚本、外部快捷方式和绝对路径不能自动推断。Agent 应先查实际调用方，按授权更新这些路径；升级器不搜索或修改其他目录。Custom scripts, shortcuts and absolute paths outside the managed framework need a scoped review; the installer does not search or rewrite other directories.

`--packages f2s` 仍作为 `fromdemotospec` 的兼容别名。新调用使用完整名称，例如 `scripts/fromdemotospec-analysis-adapter.mjs`、Brainstorm 的 `scripts/new-fromdemotospec-gap.ps1` 和 `scripts/render-fromdemotospec-handoff.ps1`；旧脚本入口只转发到新实现。Old package arguments and script entrypoints remain aliases; new callers use the full name.

已有会话不重写：`f2s-handoff` adapter ID、`f2s-design-baseline-v2` 合同 ID、`F2S-PARAM-*`、JSON 里的 `f2s_*` 字段和 `f2s-gap.json` / `f2s-handoff.md` 工件名称保留为稳定交换格式。这些是旧数据兼容标识，不是当前产品名称。Existing session IDs, protocol fields and artifact names remain stable wire formats. No creative content, decision, receipt or approval hash is rewritten for branding.

从更早独立 released 包迁移时，先使用 v1.0.0 的工具与迁移说明，再升级至本版；不将旧目录冒充新版组件。Earlier standalone releases must first migrate with the v1.0.0 tool and guide, then upgrade to this version.

## 恢复 / Recovery

每次 Apply 的 transaction 包含文件备份与目录迁移记录。使用 `rollback --target <workspace-path> --transaction <transaction-id>` 预览，加 `--apply` 才恢复；未产生后续冲突时，框架、安装记录和模块目录名一并还原。Transactions include file backups and directory relocation records. Preview rollback first; applying it restores the prior files, state and directory name if they have no later conflicts.

迁移目录内新增、删除或修改的用户文件会使回滚报告冲突，不能为回滚覆盖后续工作。先保全再人工处理。Later user changes in the moved directory block rollback rather than being overwritten.

v1.0.0 tag 保持不变。新旧目录迁移、用户数据保留、冲突、失败恢复、旧参数与旧脚本兼容均须验证；结构检查不代表游戏体验或内容批准。The v1.0.0 tag stays immutable. Engineering validation does not establish real play quality or content approval.
